BLOCKER 1 - INVALID touchSession SQL
Location: apps/api/src/persistence/postgresRepository.ts, around line 145
Current query:
UPDATE app_session SET last_seen_at = $2
WHERE id = $1 AND last_seen_at < $2 - interval '5 minutes'

GitHub Actions error:
operator does not exist: timestamp with time zone < interval
PostgreSQL code: 42883

Required correction:
Explicitly cast the repeated parameter and group the arithmetic, for example:
UPDATE app_session
SET last_seen_at = $2::timestamptz
WHERE id = $1
  AND last_seen_at < ($2::timestamptz - interval '5 minutes')

After correction, add a specific test that calls touchSession twice and verifies that a recent last_seen_at is not rewritten while an older value is updated.

BLOCKER 2 - PUBLIC-CODE COLLISION TEST GENERATES INVALID CODES
Location: postgresRepository.integration.test.ts
The test creates codes with randomBytes(3).toString("hex").toUpperCase(). Hex output can contain 0 and 1, but Kidan public codes intentionally exclude those characters. The live CI already failed with KD-E960EB violating app_user_public_code_check.

Required correction:
Use deterministic valid codes from the approved alphabet, for example:
- KD-ABCDEF
- KD-GHJKLM
Or call generatePublicCode and assert the two generated values are distinct before use. Deterministic constants are better for this collision test.

BLOCKER 3 - REUSED PHONE FIXTURE WILL VIOLATE THE UNIQUE LOOKUP HASH
Location: completeSubmission and several private-identity test calls
Many tests use +251900000000. identity_vault.phone_lookup_hash is UNIQUE, and all tests in the repository integration file share one disposable database. Once touchSession is fixed, the second candidate using that number will fail with a unique constraint violation.

Required correction:
Create a deterministic synthetic phone generator that returns a different valid number for each test user. Do not remove the production uniqueness constraint. Add one dedicated test proving that a duplicate normalized phone is handled according to the approved account-recovery/privacy policy.

BLOCKER 4 - CI IS RED
Commit 81bbd21 must not be described as a completed PostgreSQL validation milestone. Do not make the failed check a release baseline. Push a normal follow-up commit, let GitHub Actions execute it, and require a green result before Phase 01 completion.

MAJOR FINDING 1 - TELEGRAM CIPHERTEXT TEST USES THE WRONG ID
The test increments nextTelegramId into a local telegramId, then calls newUser(), which increments and uses a different ID. The assertion compares stored ciphertext to an unrelated plaintext ID and therefore cannot prove the intended mapping.

Required correction:
Issue the session with the exact local telegramId and retrieve that same user's row, or change newUser() to return both user and telegramId.

MAJOR FINDING 2 - EXPIRY IS NOT TESTED INDEPENDENTLY
The test revokes a session and then checks it at a time after expiry. The second null result can be caused entirely by revocation.

Required correction:
Use one session tested past expiry without revoking it, and a separate active session tested before and after explicit revocation.

MAJOR FINDING 3 - DELETED-USER SESSION CASE IS MISSING
The service is intended to deny suspended and deleted users. The new integration suite checks suspension only.

Required correction:
Add an independent deleted-user case for both new-session issuance and continuation of an existing session.

MAJOR FINDING 4 - HARNESS LEAKS A DATABASE IF MIGRATION SETUP FAILS
createIntegrationHarness creates a database and pool, then calls applyMigrations. If migration application throws, the function exits without ending the pool or dropping the disposable database.

Required correction:
Wrap pool creation/migration in try/catch. On setup failure, close the pool, connect through the base admin URL, DROP DATABASE ... WITH (FORCE), then rethrow the original error. Keep cleanup idempotent.

MAJOR FINDING 5 - CI ACTIONS ARE NOT PINNED AND PERMISSIONS ARE IMPLICIT
Current workflow uses actions/checkout@v4 and actions/setup-node@v4. GitHub emitted a Node.js 20 deprecation warning. Tags are mutable supply-chain references, and the workflow does not declare minimal token permissions.

Required correction:
- Add top-level permissions: contents: read
- Upgrade to reviewed Node 24-based action releases and pin to full commit SHAs.
- Current tags observed during review:
  actions/checkout v6 -> d23441a48e516b6c34aea4fa41551a30e30af803
  actions/setup-node v6 -> 249970729cb0ef3589644e2896645e5dc5ba9c38
- Add a documented process for reviewing/updating pinned SHAs.
- Add timeout-minutes to the job.
- Add workflow concurrency with cancel-in-progress for superseded branch/PR runs.

MAJOR FINDING 6 - ONE SEQUENTIAL JOB HIDES AUDIT RESULTS
When integration failed, dependency audit and diff hygiene were skipped.

Recommended correction:
Split static/unit/build/audit and PostgreSQL integration into separate jobs, or use carefully designed always() conditions and an aggregate required check. Parallel jobs provide clearer results and avoid one failure masking another.
